# 图像分析（DeepSeek Vision 桥接）

DeepSeek 等文本模型没有原生视觉能力。当用户消息中出现图片时，不要试图“凭空理解”图片，而应通过 `deepseek-vision` MCP 服务器提供的工具把图片转成文字结果，再基于这些文字继续推理。

## 触发时机

- 用户消息中包含图片标记、本地图片路径或图片 URL
- 用户刚截图（Win+Shift+S）或复制了图片，说“看看这张图”“分析我刚才复制的图”等，但没有给出文件路径
- 用户要求分析截图、海报、图表、手绘图、UI 设计稿、文档扫描件、报错信息等
- 用户要求提取图片或 PDF 中的文字（OCR）
- 用户上传多张图片并要求对比、汇总

## 剪贴板发图（对话窗口不能直接发图时）

如果用户没有提供图片路径，但表示刚截图或复制了图片：

1. 先调用 `save_clipboard_image` 工具（deepseek-clipboard 服务器），把剪贴板中的图片保存为 PNG；
2. 用返回的本地路径作为 `image` 参数，继续走下面的工具选择流程；
3. 如果剪贴板里没有图片，提示用户先按 Win+Shift+S 截图或复制一张图片，再重新发起请求。

## 工具选择

| 场景 | 工具 | 说明 |
| --- | --- | --- |
| 描述图片内容、回答图片相关问题、解读图表 / UI / 截图 | `analyze_image` | 多模态视觉模型分析，支持自定义提问 |
| 提取图片 / PDF 中的文字（自然语言返回，含代码块） | `ocr_extract` | 适合截图、文档、代码、表单 |
| 需要结构化结果（文字坐标、置信度） | `ocr_precise` | 需要配置百度 OCR 或腾讯云 OCR |

## 使用步骤

1. 从用户消息中解析图片来源：本地路径优先使用绝对路径；远程图片直接传 URL。
2. 按用户意图选择工具，把图片路径或 URL 作为 `image` 参数传入。
3. 如果用户附带了问题或指令（例如“总结这张图的要点”“提取表格”），把它作为 `prompt` 参数一并传入；没有说明时使用工具默认行为。
4. 多张图片时逐张调用 `analyze_image`（或 `ocr_extract`），再汇总对比结果。
5. 把工具返回的文字结果作为事实依据继续推理。图片中不存在的内容不要臆造。

## 注意事项

- 支持格式：PNG、JPG、JPEG、GIF、BMP、WebP、PDF。
- 若工具返回“未配置 API Key”之类的错误，说明视觉服务尚未配置：提示用户运行插件的 `scripts/setup.ps1`（Windows）或 `scripts/setup.sh`（macOS / Linux），并在 `.env` 中填入视觉模型 API Key。
- 默认使用硅基流动（SiliconFlow）的 Qwen3-VL-32B-Instruct 付费视觉模型，通用图像理解效果好；也可以切换为 Qwen3-VL-8B（更便宜）、DeepSeek-OCR（免费，适合纯文字提取）或自定义 OpenAI 兼容接口。
- 视觉服务只负责“看图”，不要让它参与主模型的代码推理或决策。
